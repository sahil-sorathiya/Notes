# 2. Spring Boot — What & Why?

## Problem Spring Boot Solves

Even with Spring, developers spent enormous time on *configuration* — XML files, bean wiring, choosing compatible library versions, setting up DispatcherServlet, DataSource, etc. Starting a new Spring project took hours before writing a single line of business logic.

## What Spring Boot Is

Spring Boot is an *opinionated*, convention-over-configuration layer on top of Spring. It auto-configures your application based on the jars on your classpath and lets you start with zero XML.

## Three Pillars of Spring Boot

1. **Auto-configuration** — detects libraries on classpath and configures beans automatically (e.g. sees H2 → creates DataSource)
2. **Starter POMs** — curated dependency bundles (`spring-boot-starter-web`, `spring-boot-starter-data-jpa`) with compatible versions
3. **Embedded server** — Tomcat/Jetty/Undertow bundled inside; run with `java -jar app.jar`, no external server needed

## Key Annotations

| Annotation | Description |
|---|---|
| `@SpringBootApplication` | Combines @Configuration + @EnableAutoConfiguration + @ComponentScan |
| `@EnableAutoConfiguration` | Triggers classpath-based auto-configuration |
| `@ComponentScan` | Scans packages for Spring-managed components |
| `@Configuration` | Marks a class as a source of bean definitions |
| `application.properties` | Single file to override any auto-configured default |
| Actuator | Built-in /health, /metrics, /env endpoints for observability |

## Spring vs Spring Boot

| | Description |
|---|---|
| **Spring** | Full control, explicit config; powerful but verbose |
| **Spring Boot** | Sensible defaults, auto-wired, production-ready out of the box |
