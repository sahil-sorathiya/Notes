# 7. Spring DI & Conflict Resolution

## Three Injection Types

### Constructor Injection ← recommended

Dependencies declared in constructor. Beans are immutable once created. Makes missing deps a compile-time/startup error. Required for circular-dep detection.

```java
public OrderService(PaymentService ps) { this.ps = ps; }
```

### Field Injection ← convenient but avoid

Uses `@Autowired` directly on fields. Concise but breaks testability (can't inject without Spring), hides dependencies, and doesn't work with `final` fields.

### Setter Injection ← for optional deps

Allows optional or late re-configuration. Use when dependency is truly optional (`@Autowired(required=false)`) or for circular dependency resolution of last resort.

---

## Conflict: Multiple Beans of the Same Type

If two beans implement the same interface and you do `@Autowired PaymentService ps`, Spring throws **NoUniqueBeanDefinitionException**.

## Resolution Strategies

| Strategy | Description |
|---|---|
| `@Primary` | Mark one implementation as the default. Spring picks it when no other hint given. |
| `@Qualifier("name")` | At the injection point: `@Autowired @Qualifier("stripePayment") PaymentService ps`. Pinpoints exactly which bean. |
| `@Profile` | Register different impls for different environments: `@Profile("dev")`, `@Profile("prod")`. Only one active per run. |
| Bean name match | If the field/param name matches a bean name, Spring auto-picks it (`paymentService` → picks bean named paymentService) |
| List/Map injection | `@Autowired List<PaymentService> services` — inject ALL matching beans; useful for strategy pattern |

## Circular Dependency Handling

If A needs B and B needs A — constructor injection fails at startup (by design, it forces you to fix the design). Setter/field injection works because Spring creates a partial bean first and injects later.

**Fix circular deps properly:** introduce a third service, or use an event/lazy proxy.

## @Lazy Injection

`@Lazy` on an injection point tells Spring to inject a proxy; the real bean is created only when first used. Breaks circular deps and speeds startup for expensive beans.

## @ConditionalOnMissingBean (Spring Boot)

Auto-configuration uses this heavily: "register this bean only if no other bean of this type exists." Allows user-defined beans to override Boot defaults cleanly.
