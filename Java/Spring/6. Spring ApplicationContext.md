# 6. Spring ApplicationContext & Implementations

## ApplicationContext vs BeanFactory

| | Description |
|---|---|
| **BeanFactory** | Root interface. Lazy bean creation. Bare minimum IoC — use only in resource-constrained environments |
| **ApplicationContext** | Extends BeanFactory + adds: event publishing, i18n messages, AOP integration, eager singleton init. *Use this always.* |

## Key Implementations

### `AnnotationConfigApplicationContext`

Bootstraps context from `@Configuration` classes or `@Component`-scanned packages. The standard choice for standalone Java apps and Spring Boot internals.

```java
new AnnotationConfigApplicationContext(AppConfig.class)
```

### `ClassPathXmlApplicationContext`

Loads bean definitions from XML files on the classpath. Legacy approach still found in older enterprise codebases.

```java
new ClassPathXmlApplicationContext("beans.xml")
```

### `AnnotationConfigWebApplicationContext`

Annotation-based context for web apps. Used by Spring MVC's `DispatcherServlet`. Registered in `web.xml` or via `WebApplicationInitializer`.

### `GenericWebApplicationContext`

Flexible, programmatically configurable web context used internally by Spring Boot's embedded server setup. Rarely instantiated directly.

### Spring Boot Context

Boot creates a `SpringApplication` that selects the right context type automatically — `AnnotationConfigServletWebServerApplicationContext` for web, `AnnotationConfigApplicationContext` for non-web. You rarely touch this directly.

## Useful Context Features

| Feature | Description |
|---|---|
| Event system | Publish/listen to events (`ContextRefreshedEvent`, custom events) via `@EventListener` |
| Environment | Access properties, profiles (`@Value`, `@Profile`) |
| Resource loading | Load classpath/filesystem resources via `ResourceLoader` |
| Parent contexts | Hierarchical contexts — child inherits parent beans (common in MVC setup) |
