# 5. Spring Beans & Their Types

## What is a Bean?

A *Spring bean* is any object whose lifecycle is managed by the Spring IoC container. You register it via `@Component`, `@Bean`, or XML — Spring creates, configures, and destroys it.

## Stereotype Annotations (Bean Registration)

| Annotation | Description |
|---|---|
| `@Component` | Generic bean — base annotation; all others are specialisations |
| `@Service` | Business logic layer — semantically marks service classes |
| `@Repository` | Data access layer — also adds exception translation (DB → Spring exception) |
| `@Controller` | Web layer — handles HTTP requests (MVC) |
| `@RestController` | @Controller + @ResponseBody — returns JSON/XML directly |
| `@Configuration` | A source of bean definitions via @Bean methods |

## Bean Scopes

| Scope | Description |
|---|---|
| `singleton` | **Default.** One instance per ApplicationContext; shared everywhere it's injected |
| `prototype` | New instance created every time the bean is requested/injected |
| `request` | One instance per HTTP request (web apps only) |
| `session` | One instance per HTTP session (web apps only) |
| `application` | One instance per ServletContext (essentially app-wide for web) |
| `websocket` | One instance per WebSocket session |

## Bean Lifecycle (Key Hooks)

1. Container reads metadata → instantiates bean
2. Dependencies injected (DI phase)
3. `@PostConstruct` method called (init hook)
4. Bean is ready and in use
5. On shutdown: `@PreDestroy` called → bean garbage collected

## Singleton Gotcha

Injecting a *prototype*-scoped bean into a *singleton* bean only injects it once — the singleton holds onto that one prototype instance forever.

**Fix:** Use `ApplicationContext.getBean()`, `@Lookup`, or `ObjectProvider<T>`.
