# 1. What is Spring & What Problem Does It Solve?

## Core Problem (pre-Spring Java EE era)

Building enterprise Java apps required heavy boilerplate — you had to manually create and wire objects, manage their lifecycles, handle transactions, and write XML-heavy EJB (Enterprise JavaBeans) configs. Objects were tightly coupled; testing was nearly impossible without a full server.

## What Spring Is

Spring is a lightweight, open-source **application framework** for Java that provides a comprehensive programming and configuration model. At its heart, it's an *Inversion of Control (IoC) container* that manages the creation, configuration, and lifecycle of objects called *beans*.

## How It Solves It

Instead of your code creating and wiring objects (*you control the flow*), Spring takes over that responsibility — you declare what you need, and the framework hands it to you. This is the Hollywood Principle: *"Don't call us, we'll call you."*

## Key Ideas Spring Introduced

| Concept | Description |
|---|---|
| IoC / DI | Framework creates & injects objects — not your code |
| POJO-based | No need to extend framework classes; plain Java objects work |
| Loose coupling | Dependencies declared via interfaces, not concrete classes |
| Testability | Inject mocks easily; no server needed for unit tests |
| AOP | Cross-cutting concerns (logging, transactions) separated cleanly |

## Before vs After Spring

**Before:**
```java
UserService us = new UserService(new UserRepo(new DB()));
// every layer manually wired, config spread in code
```

**After:**
```java
@Autowired UserService us;
// Spring resolves the full graph automatically
```
