## Spring Data

Spring Data is a Spring ecosystem project that **eliminates boilerplate data access code**. The core idea: you define *what* you want to query by writing an interface — Spring generates the actual implementation at runtime.

---

### The Problem It Solves

Before Spring Data, every repository looked like this:

```java
// Manual JDBC / JPA boilerplate
public class UserRepository {
    @PersistenceContext EntityManager em;

    public User findById(Long id) {
        return em.find(User.class, id);
    }
    public List<User> findByEmail(String email) {
        return em.createQuery("SELECT u FROM User u WHERE u.email = :email", User.class)
                 .setParameter("email", email).getResultList();
    }
    // ... repeated for every entity, every query
}
```

Same pattern, every entity, every project. Spring Data makes this disappear.

---

### The Core Idea — Repository Abstraction

You write an interface. Spring writes the class.

```java
public interface UserRepository extends JpaRepository<User, Long> {
    List<User> findByEmail(String email);
    List<User> findByAgeGreaterThan(int age);
    Optional<User> findByUsernameAndActive(String username, boolean active);
}
```

Spring Data parses the method name (`findBy`, `And`, `GreaterThan`, etc.) and generates the query automatically. No SQL, no JPQL, no implementation class needed.

---

### Repository Hierarchy

```
Repository  (marker)
  └── CrudRepository       → save, findById, findAll, delete, count
        └── PagingAndSortingRepository  → + pagination & sorting
              └── JpaRepository        → + flush, saveAndFlush, batch ops
```

You typically extend `JpaRepository<Entity, ID>`.

---

### Query Methods — How Spring Data Parses Names

| Method name | Generated query |
|---|---|
| `findByLastName(String n)` | `WHERE last_name = ?` |
| `findByAgeGreaterThan(int a)` | `WHERE age > ?` |
| `findByEmailContaining(String s)` | `WHERE email LIKE %s%` |
| `findByActiveTrue()` | `WHERE active = true` |
| `findTop5ByOrderByCreatedAtDesc()` | top 5, newest first |
| `countByDepartment(String d)` | `COUNT WHERE department = ?` |
| `deleteByExpiredTrue()` | `DELETE WHERE expired = true` |

Keywords include: `And`, `Or`, `Between`, `LessThan`, `Like`, `In`, `IsNull`, `OrderBy`, `Not`, `Top`, `First`, `Distinct`.

---

### Custom Queries — When Method Names Aren't Enough

```java
// JPQL
@Query("SELECT u FROM User u WHERE u.email = :email AND u.active = true")
Optional<User> findActiveByEmail(@Param("email") String email);

// Native SQL
@Query(value = "SELECT * FROM users WHERE created_at > NOW() - INTERVAL 7 DAY",
       nativeQuery = true)
List<User> findRecentUsers();

// Modifying query
@Modifying
@Transactional
@Query("UPDATE User u SET u.active = false WHERE u.lastLogin < :cutoff")
int deactivateInactiveUsers(@Param("cutoff") LocalDate cutoff);
```

### Pagination & Sorting

```java
// In repository — no extra code needed
Page<User> findByDepartment(String dept, Pageable pageable);

// In service
Pageable page = PageRequest.of(0, 20, Sort.by("lastName").ascending());
Page<User> result = userRepo.findByDepartment("Engineering", page);

result.getContent();      // List<User> for this page
result.getTotalPages();   // total page count
result.getTotalElements();// total record count
```

### Spring Data Sub-projects

Spring Data is not one library — it's a family, all sharing the same repository abstraction:

| Sub-project | Store |
|---|---|
| Spring Data JPA | Relational DBs via JPA/Hibernate |
| Spring Data JDBC | Relational DBs, simpler/no ORM magic |
| Spring Data MongoDB | MongoDB documents |
| Spring Data Redis | Redis key-value / cache |
| Spring Data Elasticsearch | Elasticsearch indices |
| Spring Data Cassandra | Apache Cassandra |
| Spring Data R2DBC | Reactive relational DB access |
| Spring Data REST | Auto-exposes repositories as REST endpoints |

---

### Projections — Fetch Only What You Need

```java
// Interface projection — only fetch name & email
public interface UserSummary {
    String getFirstName();
    String getEmail();
}

List<UserSummary> findByDepartment(String dept);
// SELECT first_name, email FROM users WHERE department = ?
```

Avoids fetching entire entities when only a few fields are needed.

---

### Key Annotations

| Annotation | Purpose |
|---|---|
| `@Entity` | Marks a JPA-managed class |
| `@Id` | Primary key field |
| `@GeneratedValue` | Auto-generate PK (identity, sequence, etc.) |
| `@Column` | Map field to a specific column name/constraints |
| `@OneToMany` / `@ManyToOne` | Relationships |
| `@Transactional` | Wrap method in a DB transaction |
| `@Query` | Custom JPQL or native SQL |
| `@Modifying` | Required for UPDATE/DELETE `@Query` methods |
| `@EnableJpaRepositories` | Enable JPA repo scanning (auto in Boot) |

### Spring Boot Auto-configuration

With `spring-boot-starter-data-jpa` on the classpath, Boot automatically:
- Creates a `DataSource` from `application.properties`
- Sets up `EntityManagerFactory` and `TransactionManager`
- Scans for `@Entity` classes and `JpaRepository` interfaces
- No boilerplate config needed

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.datasource.username=postgres
spring.datasource.password=secret
spring.jpa.hibernate.ddl-auto=update
```

That's all you need to get a fully working data layer.
